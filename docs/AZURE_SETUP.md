# Вход через Microsoft: настройка Azure-приложения

Nimbus не содержит встроенного Client ID. Вход работает по схеме
«принеси свой Azure-клиент»: каждый пользователь (или вы, для своей сборки)
регистрирует приложение сам и вставляет его идентификатор в настройках.

Так сделано намеренно — см. раздел «Почему так» ниже.

## 1. Зарегистрировать приложение

1. Откройте [portal.azure.com](https://portal.azure.com) → **App registrations** →
   **New registration**.
2. Заполните:

   | Поле | Значение |
   | --- | --- |
   | Name | любое, например `My Nimbus` |
   | Supported account types | **Personal Microsoft accounts only** |
   | Redirect URI | оставить пустым |

3. Откройте созданное приложение → **Authentication** →
   **Allow public client flows** → **Yes** → Save.
4. Client secret создавать **не нужно**.
5. Скопируйте **Application (client) ID** со страницы Overview.

## 2. Вставить Client ID в лаунчер

Настройки → **Аккаунт** → поле «Azure Client ID» → **Войти через Microsoft**.

Лаунчер покажет короткий код и адрес. Откройте адрес в браузере, введите код,
подтвердите вход — окно лаунчера подхватит результат само.

## 3. Пройти проверку приложения

Новые Azure-приложения обязаны получить разрешение на доступ к Minecraft API.
Пока его нет, первые три шага авторизации (Microsoft → Xbox Live → XSTS)
проходят успешно, а последний отвечает **403**.

Заявка подаётся по форме: <https://aka.ms/mce-reviewappid>

Лаунчер распознаёт этот случай и показывает понятное сообщение, а не «403».

## Известные ошибки и что они значат

| Сообщение | Причина |
| --- | --- |
| приложение не найдено или ему запрещён публичный вход | неверный Client ID либо не включён «Allow public client flows» |
| Minecraft API отклонил приложение (403) | приложение не прошло проверку из шага 3 |
| У этого аккаунта Microsoft нет профиля Xbox | нужно один раз зайти на xbox.com и создать профиль |
| Это детский аккаунт | аккаунт нужно добавить в семейную группу Microsoft |
| На этом аккаунте нет Minecraft: Java Edition | игра не куплена на этом аккаунте |
| Аккаунту требуется подтверждение для взрослых | ограничение Xbox Live в некоторых регионах |

## Почему именно так

Разрешение `XboxLive.signin`, без которого вход невозможен, Microsoft выдаёт
через Xbox Developer program (ID@Xbox) — то есть рассчитано на студии, а не на
сторонние лаунчеры. Единственная схема, которая работает независимо от решения
Microsoft по конкретной заявке, — Client ID на стороне пользователя.

Технические детали: вход идёт по OAuth 2.0 **device code flow**, поэтому
лаунчеру не нужен ни локальный HTTP-сервер, ни redirect URI. Обязательно
используется тенант `consumers` — `common` и тенант организации дают
невнятные ошибки, и войти можно только личным аккаунтом Microsoft.

Токены хранятся в `%APPDATA%\NimbusClient\account.json` отдельно от
`config.json`, потому что конфиг целиком отдаётся в интерфейс при каждом
запуске, а токенам там не место.
