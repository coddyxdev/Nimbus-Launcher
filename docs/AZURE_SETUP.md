# Вход через Microsoft

В сборку Nimbus встроен собственный Azure Client ID, поэтому обычному
пользователю ничего настраивать не нужно: достаточно нажать
**«Войти через Microsoft»** в онбординге или в Настройках → **Аккаунт**.

Поле «Azure Client ID» в настройках необязательное: оно спрятано под пунктом
«Своё приложение Azure» и нужно только тем, кто хочет входить через свою
регистрацию в Azure. Пустое поле означает «использовать встроенный id».

## Как проходит вход

Лаунчер показывает короткий код и адрес и сам открывает страницу Microsoft в
браузере. Пользователь вводит код, подтверждает вход — лаунчер подхватывает
результат сам, проверяет наличие Minecraft: Java Edition и забирает ник, UUID и
скин из аккаунта. Аккаунтов можно добавить несколько и переключаться между ними.

Вход идёт по OAuth 2.0 **device code flow**, поэтому лаунчеру не нужен ни
локальный HTTP-сервер, ни redirect URI. Используется тенант `consumers` —
`common` и тенант организации дают невнятные ошибки, и войти можно только личным
аккаунтом Microsoft.

Токены хранятся в `%APPDATA%\NimbusClient\account.json` отдельно от
`config.json`, потому что конфиг целиком отдаётся в интерфейс при каждом
запуске, а токенам там не место.

## Своё приложение Azure (необязательно)

1. Откройте [portal.azure.com](https://portal.azure.com) → **App registrations** →
   **New registration**.
2. Заполните:

   | Поле | Значение |
   | --- | --- |
   | Name | любое, например `My Nimbus` |
   | Supported account types | **Personal Microsoft accounts only** |
   | Redirect URI | оставить пустым |

3. Откройте созданное приложение → **Authentication** →
   **Allow public client flows** → **Yes** → Save.
4. Client secret создавать **не нужно**. Разрешения API (в том числе `User.Read`)
   добавлять тоже не нужно: вход использует scope `XboxLive.signin`, который в
   портале не настраивается.
5. Скопируйте **Application (client) ID** со страницы Overview и вставьте его в
   Настройки → **Аккаунт** → «Своё приложение Azure» → Azure Client ID.

Новые Azure-приложения обязаны отдельно получить доступ к Minecraft API. Пока
его нет, первые три шага авторизации (Microsoft → Xbox Live → XSTS) проходят
успешно, а последний отвечает **403**. Заявка подаётся по форме:
<https://aka.ms/mce-reviewappid>. Лаунчер распознаёт этот случай и показывает
понятное сообщение, а не «403».

## Для тех, кто собирает Nimbus из исходников

Встроенный идентификатор — константа `BUILT_IN_CLIENT_ID` в
`src-tauri/src/auth.rs`. Если оставить её пустой, кнопка входа в сборке
отключается и пользователю предлагается указать свой id. Client ID публичного
клиента не является секретом, но заявка в Mojang и лимиты привязаны к той
регистрации, чей id вписан в сборку.

## Известные ошибки и что они значат

| Сообщение | Причина |
| --- | --- |
| приложение не найдено или ему запрещён публичный вход | неверный Client ID либо не включён «Allow public client flows» |
| Minecraft API отклонил приложение (403) | приложение не получило доступ к Minecraft API |
| У этого аккаунта Microsoft нет профиля Xbox | нужно один раз зайти на xbox.com и создать профиль |
| Это детский аккаунт | аккаунт нужно добавить в семейную группу Microsoft |
| На этом аккаунте нет Minecraft: Java Edition | игра не куплена на этом аккаунте |
| Аккаунту требуется подтверждение для взрослых | ограничение Xbox Live в некоторых регионах |
