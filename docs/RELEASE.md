# Публикация релизов и автообновление

Начиная с 1.7.3 код и сборки живут в одном **публичном** репозитории
`coddyxdev/Nimbus-Launcher`. Релизы публикует GitHub Actions по пушу тега.

Репозиторий обязан оставаться публичным: апдейтер скачивает `latest.json` и
инсталлятор **без авторизации**, а вложения релизов приватного репозитория
отдают анонимным запросам 404. Зашить токен в клиент нельзя — он окажется у
всех пользователей.

## Текущая конфигурация

| Что | Значение |
| --- | --- |
| Репозиторий с кодом и релизами | `coddyxdev/Nimbus-Launcher` (**должен быть публичным**) |
| Endpoint | `https://github.com/coddyxdev/Nimbus-Launcher/releases/latest/download/latest.json` |
| Старый репозиторий | `coddyxdev/Nimbus-Launcher-releases` — только зеркало `latest.json` |
| Публичный ключ | прописан в `src-tauri/tauri.conf.json` → `plugins.updater.pubkey` |
| Идентификатор ключа | `2A5A244088956781` |
| Приватный ключ | `%USERPROFILE%\.tauri\nimbus.key` (зашифрован паролем) |

## Мост для старых сборок

Адрес проверки обновлений компилируется внутрь приложения. У всех сборок **до
1.7.3 включительно предыдущих версий** зашит старый адрес
`Nimbus-Launcher-releases`, поэтому они продолжают спрашивать старый
репозиторий.

Чтобы они не остались без обновлений, `release.yml` после публикации копирует
`latest.json` в старый репозиторий. Сам установщик туда **не** копируется:
манифест ссылается на файл в основном репозитории, и обе цепочки ведут к одному
и тому же бинарнику.

Когда пользователей на 1.7.2 и старше не останется, удалите из `release.yml` два
шага зеркалирования и заархивируйте старый репозиторий.

## Секреты репозитория

`Nimbus-Launcher` → Settings → Secrets and variables → Actions:

| Имя секрета | Значение |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | всё содержимое файла `%USERPROFILE%\.tauri\nimbus.key` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пароль, заданный при генерации ключа |
| `RELEASES_TOKEN` | fine-grained PAT с правом Contents: Read and write на `Nimbus-Launcher-releases` (нужен только для зеркала) |

Публикацию в основной репозиторий делает встроенный `GITHUB_TOKEN`, отдельный
токен для неё не нужен.

Приватный ключ существует в единственном экземпляре: **потеряете — не сможете
выпускать обновления для уже установленных копий.** Держите резервную копию в
менеджере паролей. Пароль от ключа меняйте, не меняя сам ключ, иначе
разошедшиеся сборки перестанут принимать обновления.

## Как выпустить релиз

Версия берётся из `src-tauri/tauri.conf.json` (`version`) — поднимите её перед
тегом, иначе установленная копия не увидит обновление. Версию нужно поднять
сразу в пяти местах: `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`,
`package.json`, `package-lock.json` (две записи) и бейдж в `README.md`;
`src-tauri/Cargo.lock` обновится сам после `cargo check`.

```bat
cd /d "C:\AIWorkspace\Nimbus Launcher"
git add -A
git commit -m "Nimbus Client 1.7.4"
git tag v1.7.4
git push origin main --tags
```

Больше ничего делать не нужно: тег `v*` запускает `.github/workflows/release.yml`,
который собирает NSIS-инсталлятор, подписывает его ключом, публикует релиз и
зеркалит манифест. Собирать и подписывать локально не требуется.

В релизе должно оказаться три файла:

- `Nimbus.Client_<версия>_x64-setup.exe` — инсталлятор;
- `Nimbus.Client_<версия>_x64-setup.exe.sig` — подпись;
- `latest.json` — манифест с версией, ссылкой и подписью.

Пробелы в имени файла GitHub заменяет точками, поэтому ссылка в манифесте
содержит `Nimbus.Client`, а не `Nimbus Client`. Если формируете манифест
вручную, обязательно сверьте ссылку с фактическим адресом вложения.

## Проверка

Быстрая проверка — открыть endpoint в браузере в режиме инкогнито: должен
отдаться JSON, а не страница логина GitHub.

Полная проверка — установить предыдущую версию, запустить её и включить режим
разработчика (Настройки → Обслуживание). В логе появится одна из записей:

| Запись | Значение |
| --- | --- |
| `updater: доступна версия 1.7.4` | всё работает, сверху появится плашка обновления |
| `updater: установлена последняя версия` | версии совпадают |
| `updater: не настроен` | в конфиге остались placeholder-ы `REPLACE_*` |
| `updater: проверка не удалась — ...` | сеть, репозиторий стал приватным или `latest.json` отсутствует |

## Частые ошибки

| Ошибка | Причина |
| --- | --- |
| `A public key has been found, but no private key` | сборка идёт без `TAURI_SIGNING_PRIVATE_KEY` |
| `incorrect updater private key password` | неверный `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` |
| `signature verification failed` у клиента | манифест и установщик из разных сборок, либо пара ключей заменена после предыдущего релиза |
| `invalid target_commitish` | в старом репозитории нет ветки `main` — создайте README |
| `Resource not accessible by integration` | `RELEASES_TOKEN` истёк или выдан без прав Contents: Read and write |
| Обновление не приходит на 1.7.2 | не отработало зеркало `latest.json` в старом репозитории |
